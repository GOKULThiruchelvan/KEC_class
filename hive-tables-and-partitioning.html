Apache Hive: Managed Tables, External Tables and Partitioning

This document presents one continuous Hive script. It begins with the creation of a database and proceeds through managed and external tables, static partitioning and dynamic partitioning. The code is shown in the order in which it should be executed, and each block is followed by its expected result.

1. Create the Database

A database in Hive is a namespace that groups related tables together. All tables below are created inside it.

Code

CREATE DATABASE college_db;

USE college_db;

Result

OK. The database college_db is created and selected as the current database.

2. Managed Table

A managed (internal) table is one for which Hive controls both the metadata and the data. The data is stored in the Hive warehouse location, and dropping the table deletes both.

Code

CREATE TABLE employees (
    id INT,
    name STRING,
    department STRING,
    salary INT
);

INSERT INTO employees VALUES
(1, 'Gokul', 'IT', 30000),
(2, 'Arun', 'HR', 40000),
(3, 'Priya', 'IT', 50000);

SELECT * FROM employees;

Result

idnamedepartmentsalary
1GokulIT30000
2ArunHR40000
3PriyaIT50000

3. External Table

An external table is one for which Hive manages only the metadata. The data remains at a location that the user specifies, so dropping the table does not delete the data.

Code: create the HDFS directory (terminal)

hdfs dfs -mkdir -p /user/hive/external/employees

Code: create the external table (Hive)

CREATE EXTERNAL TABLE employees_ext (
    id INT,
    name STRING,
    department STRING,
    salary INT
)
ROW FORMAT DELIMITED
FIELDS TERMINATED BY ','
STORED AS TEXTFILE
LOCATION '/user/hive/external/employees';

Code: create the CSV file (Windows CMD) and upload it to HDFS

echo 101,Gokul,IT,30000 > employees.csv
echo 102,Arun,HR,40000 >> employees.csv
echo 103,Priya,IT,50000 >> employees.csv

hdfs dfs -put employees.csv /user/hive/external/employees/

Code: read the data (Hive)

SELECT * FROM employees_ext;

Result

idnamedepartmentsalary
101GokulIT30000
102ArunHR40000
103PriyaIT50000

Code: DROP TABLE on both types

DROP TABLE employees;

DROP TABLE employees_ext;

hdfs dfs -ls /user/hive/external/employees/

Result

StatementEffect
DROP TABLE employees;Metadata and data are both deleted.
DROP TABLE employees_ext;Only metadata is deleted.
hdfs dfs -ls ...The file /user/hive/external/employees/employees.csv is still present.

Both partitioning examples read from a table named student_source. It is created here so that the script runs from start to finish without any missing table.

5. Static Partitioning

In static partitioning, the user specifies the partition value manually in the INSERT statement, and Hive stores the records in exactly that partition.

Code

CREATE TABLE students_static (
    name STRING,
    department STRING
)
PARTITIONED BY (year INT);

INSERT INTO TABLE students_static
PARTITION (year=2025)
VALUES
('Priya', 'AIDS'),
('Ravi', 'CSE');

SHOW PARTITIONS students_static;

Result

PartitionRecords
year=2025Priya, Ravi

Only the partition that was named in the statement exists.

6. Dynamic Partitioning

In dynamic partitioning, the user does not name each partition value. Hive reads the partition column from the input data and creates the partitions automatically.

Code

SET hive.exec.dynamic.partition=true;

SET hive.exec.dynamic.partition.mode=nonstrict;

CREATE TABLE students_dynamic (
    name STRING,
    department STRING
)
PARTITIONED BY (year INT);

INSERT INTO TABLE students_dynamic
PARTITION (year)
SELECT name, department, year
FROM student_source;

SHOW PARTITIONS students_dynamic;

Result

PartitionRecords
year=2024Arun, Kumar
year=2025Priya, Ravi
year=2026Divya

7. Summary

TopicKey Point
Managed TableHive manages metadata and data; DROP removes both.
External TableHive manages metadata only; DROP leaves the data in place.
Static PartitioningThe user specifies the partition value, for example year=2025.
Dynamic PartitioningHive derives partition values from the data, using PARTITION (year).
