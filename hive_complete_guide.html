Hive on Windows: Complete Guide

From first setup to ACID tables, constraints and group queries. Tested stack: Java 8, Hadoop 2.7.x, Hive 2.1.0, Derby 10.14.2.0.

Two rules: use an Administrator Command Prompt, never PowerShell. Click Copy on a block and paste the whole block.

1One-time setup

Do this once per computer. If Hive already starts and ACID works, skip it. ஒரு தடவை மட்டும் செய்ய வேண்டியவை.

1a. Environment variables

setx HADOOP_HOME "C:\hadoop" /M
setx HIVE_HOME "C:\hive" /M
setx DERBY_HOME "C:\derby" /M
No \bin at the endHADOOP_HOME must be exactly C:\hadoop. setx changes only new windows, so close the window and open a new one. To fix the current window at once, run set HADOOP_HOME=C:\hadoop.

1b. Copy the Derby client jars into Hive

copy C:\derby\lib\derbyclient.jar C:\hive\lib\
copy C:\derby\lib\derbytools.jar C:\hive\lib\

1c. Format HDFS (new installs only)

hdfs namenode -format
CarefulThis erases all HDFS data. Never run it on a machine that already has data.

1d. Create the HDFS folders for Hive

Start HDFS first (see step 2), then:

hdfs dfs -mkdir -p /user/hive/warehouse /tmp
hdfs dfs -chmod -R 777 /user/hive/warehouse /tmp

1e. Create the metastore (Derby must be running)

schematool -dbType derby -initSchema
ExpectedThe last line says schemaTool completed.

1f. Add the ACID transaction tables to the metastore

ACID tables need extra tables (NEXT_LOCK_ID, TXNS, HIVE_LOCKS). If they are missing, an ACID insert fails with Table/View 'NEXT_LOCK_ID' does not exist. Quit Hive first, keep the Derby window open, then:

set DERBY_HOME=C:\derby
C:\derby\bin\ij

At the ij> prompt, enter these lines one by one:

connect 'jdbc:derby://localhost:1527/metastore_db';
run 'C:/hive/scripts/metastore/upgrade/derby/hive-txn-schema-2.1.0.derby.sql';
exit;
ExpectedA series of 0 rows inserted/updated/deleted and 1 row inserted lines, then back at the normal prompt. Do it only once.

2Start every time

Order matters: Derby first, then Hadoop, then Hive.

Window 1: Derby (keep it open)

set DERBY_HOME=C:\derby
cd C:\derby\bin
StartNetworkServer -h 0.0.0.0
ExpectedMessage: started and ready to accept connections on port 1527.

Window 2: Hadoop and Hive

start-dfs.cmd
start-yarn.cmd
jps
set HADOOP_HOME=C:\hadoop
hive
Expectedjps lists NameNode, DataNode, ResourceManager, NodeManager. Then the hive> prompt appears. The SLF4J and log4j2 lines are only warnings.

3Create a table and insert

This first table is a normal table. It does not follow ACID. Use a fresh Hive session, without any ACID settings.

create database demo_db;
use demo_db;

create table emp_normal (id int, name string, dept string, salary int);

insert into emp_normal values
  (1,'Gokul','IT',30000),
  (2,'Arun','HR',40000),
  (3,'Priya','IT',50000),
  (4,'Kavin','Sales',35000),
  (5,'Divya','HR',45000);

select * from emp_normal;
ExpectedFive rows. The insert runs a MapReduce job and takes a few seconds.
describe formatted emp_normal;
Look atTable Parameters. There is no transactional entry.

4Update and delete fail on it

Insert works, but update and delete need an ACID table. இங்க error வருவதுதான் demo.

update emp_normal set salary = 55000 where id = 1;
delete from emp_normal where id = 2;
Expected error (this is the point)FAILED: SemanticException [Error 10294]: Attempt to do update or delete using transaction manager that does not support these operations.

The data is unchanged, so the group queries in step 7 still use the original five rows.

5Create an ACID table

Same columns, but built for ACID. Update and delete now work.

5a. ACID settings

set hive.support.concurrency=true;
set hive.exec.dynamic.partition.mode=nonstrict;
set hive.txn.manager=org.apache.hadoop.hive.ql.lockmgr.DbTxnManager;
set hive.compactor.initiator.on=true;
set hive.compactor.worker.threads=1;
Every new sessionThese last only for the current Hive session. Run them again after each restart of Hive, before touching an ACID table. Do not add hive.enforce.bucketing: Hive 2.x removed it and reports that it does not exist.

5b. Create the table and insert

create table emp_acid (id int, name string, dept string, salary int)
clustered by (id) into 2 buckets
stored as orc
tblproperties ('transactional'='true');

insert into emp_acid values
  (1,'Gokul','IT',30000),
  (2,'Arun','HR',40000),
  (3,'Priya','IT',50000),
  (4,'Kavin','Sales',35000),
  (5,'Divya','HR',45000);

select * from emp_acid;

5c. Update and delete

update emp_acid set salary = 55000 where id = 1;
select * from emp_acid;

delete from emp_acid where id = 2;
select * from emp_acid;
ExpectedGokul salary becomes 55000, then Arun row disappears. No error.

6Constraints: primary key and foreign key

Hive 2.1.0 accepts these only as informational constraints, written with disable novalidate. Hive does not enforce them.

6a. Primary key

create table dept (
  dept_id int,
  dept_name string,
  primary key (dept_id) disable novalidate
);

insert into dept values (1,'IT'),(2,'HR'),(1,'Sales');

select * from dept;
Expecteddept_id 1 appears twice and there is no error. MySQL would reject the duplicate; Hive does not check it.

Find the duplicate yourself:

select dept_id, count(*) as cnt
from dept
group by dept_id
having count(*) > 1;

6b. Foreign key

create table emp_fk (
  id int,
  name string,
  dept_id int,
  primary key (id) disable novalidate,
  constraint fk_dept foreign key (dept_id)
    references dept(dept_id) disable novalidate
);

insert into emp_fk values (1,'Gokul',1),(2,'Arun',99);

select * from emp_fk;
describe formatted emp_fk;
Expecteddept_id 99 does not exist in dept, yet the insert succeeds. The describe output lists both constraints.

7Group queries

Run these on emp_normal, which still has the original five rows.

Query 1: employees per department

select dept, count(*) as emp_count
from emp_normal
group by dept;
deptemp_count
IT2
HR2
Sales1

Query 2: average and highest salary per department

select dept, avg(salary) as avg_sal, max(salary) as max_sal
from emp_normal
group by dept;
deptavg_salmax_sal
IT4000050000
HR4250045000
Sales3500035000

Query 3: departments with a total salary above 70000

select dept, sum(salary) as total
from emp_normal
group by dept
having sum(salary) > 70000
order by total desc;
depttotal
HR85000
IT80000
Rememberwhere filters rows before grouping. having filters groups after grouping. Row order in group by output can differ.

When you finish

quit;

Then run stop-yarn.cmd and stop-dfs.cmd, and close the Derby window.
